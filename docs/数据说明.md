# 数据说明

## 当前标的

- `sh.000300`：沪深300指数，用来观察宽基指数走势，不是可直接买卖的证券。
- `sh.510300`：宽基 ETF 示例，仅用于学习数据处理与回测，不代表推荐购买。

## 来源优先级

1. AKShare：主来源，使用其文档公开接口获取日线。
2. BaoStock：交叉核对来源。

真实数据更新时，两个来源分别保存到 `data/raw/`。主来源通过校验后写入
`data/curated/`，并同步到 `data/finance_lab.duckdb`。

## 标的与文件身份

标的使用小写 ASCII 命名空间、一个点和六位 ASCII 数字，例如 `sh.510300` 或
`demo.000300`；命名空间以字母开头，长度最多 16 位，只允许小写字母与数字。
整理文件名对应为 `sh_510300.parquet`、`demo_000300.parquet`。这只是格式约束，
是否支持采集、是否允许账户回测仍由配置与现有业务校验决定。

同一个原始或整理文件只能包含一个标的。采集响应必须与请求标的一致；读取或增量
合并时，文件内容也必须与目标标的一致。`SH.510300`、`sh_510300`、空值、数字类型
和全角数字不会被自动转换成规范标的。不同来源仍可合并到同一标的的整理文件。

健康检查中的 `invalid_symbol` 表示格式错误，`mixed_symbols` 表示混入多个标的，
`symbol_filename_mismatch` 表示文件名与内容不一致，`missing_symbol` 表示没有可核验
的标的。遇到错误时保留原文件，先核对原始快照与来源，不自动重命名或覆盖修复。
数据库同步先预检文件身份，失败时保留原有行情表；预检与实际 SQL 读取在同一把
行情锁内完成，使用项目接口的另一个更新任务不能插入其中。

## 并发更新与读取

同一项目使用 `data/market_data.lock` 协调行情访问。完整更新从抓取前到更新摘要
发布结束持续持锁；原始/整理数据保存、数据库同步、整理数据读取、数据清单、摘要
读取、数据校验及模拟盘行情快照也使用同一把锁。同一线程内部的嵌套调用允许重入；
不同项目互不影响。当前采用排他锁，同时读取也可能提示繁忙。

遇到“已有行情数据任务正在运行，请稍后重试”时，等待当前任务结束后再运行，
不要删除锁文件。锁文件在正常完成后仍会保留，文件存在不等于任务仍在运行。
正常退出、异常退出或进程终止会释放持锁状态；不会自动排队或后台重试。
CLI 遇到锁冲突非零退出；每日自动化会记录失败步骤，不继续模拟记账。

这只保护遵守上述接口的并发调用，不拦截手工改文件。多次独立 API 调用之间仍可能
发生更新。若进程在发布多个文件的中途崩溃，已经发布的文件不会自动回滚；下面的
状态协议负责隔离，跨文件恢复仍未实施，不能把这些改进当成完整的批次事务。

## 未完成更新的隔离与诊断

完整更新在修改行情之前写入 `data/market_update_state.json`，记录版本、批次、请求
日期、配置标的、开始时间和发布阶段。整理行情、数据库与摘要处理完成后，最后写入
`completed` 并绑定摘要 SHA-256。异常尽力记录 `failed`；强制终止或异常记录写入失败
时，之前的 `updating` 仍会阻止后续使用。结束进程或等待锁释放不能解除这种隔离。

| 诊断状态 | 含义与处理 |
| --- | --- |
| `legacy` | 旧项目没有新协议记录；保留原校验，不证明历史更新完整 |
| `updating` / `failed` | 批次未完成；阻止读取、回测、模拟、新更新和独立写入 |
| `completed` 且 `blocked=false` | 发布完整性通过；仍须检查来源、身份、日期与行情健康 |
| `invalid` 或 `blocked=true` | 状态损坏/未知或摘要不匹配，保留文件并停止正常使用 |

在项目环境中运行：

```powershell
finance-lab data-update-status
```

命令取得行情锁后输出 JSON，不抓取、不修复、不推进模拟账户，不修改状态文件、行情
或账本；运行时锁文件可能创建/更新时间。发布完整、数据源成功或旧项目兼容返回 0；
已提交但本次来源部分/全部失败返回 2；未完成、无法解析、摘要不符或锁繁忙返回非零。
坏 JSON 不直接回显原始内容；合法状态会报告批次、请求范围、阶段、`source_outcome`
及必要的错误类型。

`completed` 只表示批次文件提交完成，不代表本次数据源全部成功。更新摘要的 `status`
另记为 `success`、`partial_sources` 或 `failed`；每个数据源还记录收到/接受/拒绝行数、
过滤原因、失败阶段和实际日期范围。`fetch` 在全部失败时返回 2，部分失败时返回 3；
`all` 对部分失败也返回非零，不继续生成新回测。每日模拟盘遇到部分或全部来源失败时
停止推进，旧数据保持可读但不冒充本次成功。陈旧数据仍须单独检查。历史静态报告
不删除，但只代表生成时的结果，不能用旧报告证明当前数据健康。

`finance-lab validate` 是只读整理行情校验。没有已发布的整理 Parquet、正式文件损坏、
或字段校验失败都会返回非零；报告中的 `status`、`stage`、`data_committed=false` 和
`next_action` 分别说明结果、失败阶段、未修改行情及下一步。临时发布文件不当作正式
行情，也不会被这个命令删除。校验结果不替代数据新鲜度和来源完整性检查。

CLI 的日期参数要求严格 `YYYY-MM-DD`；`--costs` 情景列表只接受非负有限数字，
`--shorts` / `--longs` 等窗口列表只接受互不重复的正整数。列表中的空项也会在
解析阶段被拒绝，命令不会进入抓取或报告生成。其他数值参数的统一预检仍待后续批次。

`manifest` 找不到已发布的整理行情、`account` 找不到 `config/instruments.json` 时，
会以非零退出并输出 `error_code`、`stage`、`data_committed=false` 和 `next_action`；
这两种情况不会生成业务报告。其他命令的缺文件及写入失败语义仍在分批完善。
`dataset-check --expected-dataset-id <完整64位ID>` 可在研究前只读核验当前整理行情。
匹配且健康状态不是错误时，输出单个 JSON（`status=verified`），退出码为 0；
不匹配、无已发布行情、健康状态错误或锁被其他任务占用时非零退出，不生成研究报告。
警告状态仍可能包含陈旧数据或不复权数据，必须查看 `manifest` 的具体说明。
核验只代表运行当刻；后续每条研究命令仍要附带相同 `--expected-dataset-id`，
不能把一次检查当成整段研究会话的数据冻结。
`filename-audit` 在项目行情锁内只读审计 `data/curated` 的直接子项文件名。
它报告非规范 Parquet 候选名、跨平台可移植键碰撞，以及候选目录/符号链接；
发现风险时返回非零 JSON，旧暂存命名空间只计数，不自动重命名、删除或读取文件内容。
空目录会显示候选数为 0，但不表示行情已校验通过；内容、来源和日期仍须使用
`validate` 与 `manifest` 检查。跨平台别名规则是保守风险提示，不保证每个文件系统
都会实际覆盖；处理历史文件需先保留快照并人工批准迁移方案。
`account-all`、`experiment-all`、`walk-forward-all`、`cost-stress-all`、
`parameter-test-all`、`execution-test-all`、`compare-all` 缺少同一配置时也会在
批量执行前返回相同结构的非零错误，不生成部分报告。
若上述账户或批量研究命令读到格式损坏、空列表或缺少必需字段的配置，
会返回 `invalid_instruments_config` 与 `stage=load_config`；先修正配置再重试。
此预检不替代行情数据校验，也不把权限或磁盘 I/O 故障误报为配置格式错误。

`account`、`backtest`、`experiment`、`walk-forward`、`cost-stress`、
`parameter-test`、`execution-test`、`compare` 若找不到请求标的的已发布整理行情，
返回 `missing_symbol_data`、`stage=load_curated` 和补救建议，不生成研究报告。
检查文件前仍核对行情更新隔离状态；若项目处于隔离状态，应先按隔离诊断处理。

批量账户和研究命令是逐标的生成报告，不具备整批回滚能力。若中途失败，
退出码为非零，结果中的 `reports_confirmed` 只列已确认返回的报告路径，
`failed_symbol` 指向正在处理的标的，`current_report_state=unknown` 表示该标的
可能留下部分文件。`data_committed=false` 仅指本批未写入行情或模拟账本，
不表示报告文件被回滚。请检查现有输出后再重试，勿把它们视为完整批次。

基础回测、账户账本及六类历史研究报告的 HTML/JSON、PNG 图表和 CSV
采用逐文件临时写入和替换；同名旧文件在本文件替换失败时保留。
该措施不保证一份报告的多个文件同时切换，也不覆盖前向模拟盘报告或
断电持久性；失败时仍需逐一核对输出。

八类历史研究报告及数据健康报告都有与 HTML 同名的 `.bundle.json` 完成标记，
记录各自 HTML、JSON，以及适用的 PNG/CSV 的 SHA-256 与大小；标记只在全部成员写完后发布。
运行 `finance-lab report-verify --report <报告HTML路径>` 可只读核验；完整时退出码 0，
缺标记、成员缺失、哈希不符或标记无效时非零退出。旧报告没有标记时显示
`marker_missing`，不会自动补写或修改。完成标记不是整组事务，也不证明数据质量、
策略有效或真实资金可用；前向模拟盘报告暂不在本机制内。

遇到隔离：保留项目目录、原始快照和状态记录，先查看诊断；不要删除/改写标记，
不要反复执行更新试图解除隔离，也不要回滚整个共享 DuckDB（其中可能含模拟账本）。
本版提供恢复材料准备、离线候选重建与复核。解除隔离和正式目录切换仍需后续验收。

此协议不保证机器断电后的持久性、不追溯升级前的历史中断、不拦截手工或外部程序
改文件，也不把独立存储调用变成完整批次事务。分开多次调用的研究输入快照绑定仍待完善。

## 保存与复核恢复材料

在项目根目录执行以下示例，目标必须位于项目之外、父目录已存在且目标自身尚不存在：

```powershell
finance-lab data-recovery-prepare --destination "..\recovery-copy-20260923"
finance-lab data-recovery-verify --bundle "..\recovery-copy-20260923"
```

准备命令使用 `FINANCE_LAB_ROOT` 或程序默认项目根；源项目及其 `data` 目录必须已经存在，
不会初始化缺失的源目录。复核命令只需要材料目录，可以在原项目移动之后独立执行。
材料包含本地账户信息，不要直接上传到公开 GitHub 仓库。

准备时依次取得模拟盘锁和行情锁；忙碌时失败，请稍后重试。复制 `config/`、`data/`
中的普通文件（仅排除两个运行时锁文件），以及存在时的 `outputs/update_summary.json`。
空目录、缺失项、失败标记和临时残留按现场保存；不复制代码、虚拟环境或其他报告/日志。
这不是完整项目备份，也不是数据库在线热备。

副本位于 `snapshot/`；最终 `recovery_manifest.json` 记录文件集合、大小和 SHA-256。
`recovery_check.json` 记录最近一次复核，绑定清单指纹、检查时间和程序版本。
复核每次重新读取和计算，不信任旧检查结果；新增、缺失、变化的负载文件均导致失败。
清单不是数字签名，不抵御同时篡改文件和清单的攻击。

输出分开解释：

| 字段 | 含义 |
| --- | --- |
| `copy_integrity` | 材料文件集合和指纹是否通过检查，不代表行情一致或新鲜 |
| `ledger_audit.status` | `passed`、`not_present`、`unsupported` 或 `failed` |
| `market_status` | 原行情状态诊断；失败/中断/坏标记按原样保留 |
| `ready_for_use` | 本阶段始终为 `false`，不能据此切换正式目录 |
| `ok` | 文件校验通过，且账本检查通过或明确不存在账本 |

`ok=true` 返回 0，仅表示恢复材料检查成功。账本检查只支持当前 schema 2，拒绝未知、
旧版和残缺结构，不自动迁移；事件、现金、份额和权益采用现有只读审计。
损坏数据库、账本不通过、文件校验或路径检查失败均返回非零，原文件不会被替换。
原行情即使处于隔离中，也可以保存材料；复制成功不等于隔离解除。

如果发现 `finance_lab.duckdb.wal`，先关闭相关程序再检查；仍存在时保留现场，不删除 WAL。
目录链接、Windows 目录联接、已有目标和源目标重叠也会被拒绝。源数据、配置与状态字节不变；
取得锁可能创建或更新时间戳的两个锁文件属于明确的运行时副作用。

复制中断或磁盘错误后保留目标。缺少最终清单的材料包不完整；只有清单也不能跳过复核。
失败输出包含阶段和目标路径，不包含数据正文。重试准备使用另一个全新目录，不能续写或覆盖旧目录。
离线行情候选重建的操作见下一节。不要删除标记、手工清空账本或拿旧数据库覆盖当前项目。

## 从明确的原始快照生成离线候选

先使用上面的命令创建并通过恢复材料复核。新建一个 UTF-8 JSON 选择文件，必须给
`config/instruments.json` 中每个标的指定恰好一份材料包中的原始 Parquet：

```json
{
  "schema_version": 1,
  "bundle_id": "从 recovery_manifest.json 复制材料包 ID",
  "items": [
    {
      "symbol": "sh.000300",
      "raw_path": "data/raw/baostock/sh_000300/实际文件名.parquet",
      "sha256": "从 recovery_manifest.json 中同一路径的文件条目复制 SHA-256"
    }
  ]
}
```

上面是格式示例，不是可直接用于真实数据的选择文件。每个标的都要从材料包清单中
核对 `raw_path` 和 SHA-256；本命令不按时间自动选文件。新目标的父目录必须已存在，
候选目录必须尚不存在，并位于材料包和正式项目之外：

```powershell
finance-lab data-recovery-rebuild --bundle "..\recovery-copy-20260923" --selection "..\selection.json" --destination "..\market-candidate-20260925"
finance-lab data-recovery-candidate-verify --bundle "..\recovery-copy-20260923" --candidate "..\market-candidate-20260925"
```

候选在 `snapshot/data/curated/` 下保存重新生成的整理行情，
`snapshot/data/finance_lab.duckdb` 内只重建 `daily_prices` 表。程序对全部模拟账本表
和账户状态做前后核验。`candidate_report.json` 记录所选原始文件、实际首尾交易日、
行数、来源、警告、数据库行数和账本指纹；复核命令每次重新计算。缺数据时不会
自动补齐，实际日期范围不代表覆盖所有所需交易日。

候选保留原来的行情隔离状态，`ready_for_use` 始终为 `false`，不可直接用于每日
模拟任务或替换正式目录。失败时目录保留作排查，重试应选择新的候选路径。

## 复权

第一阶段统一使用不复权数据 `adjustment=none`，避免不同来源复权定义不一致。
这意味着 ETF 的长期持有收益暂未计入分红再投资，不能直接当成完整投资收益。

## 成交量

AKShare 返回值通常以“手”为单位，BaoStock 通常以“股”为单位，因此字段中保留
`volume_unit`，交叉核对时不直接比较成交量。

## 合成数据

恢复候选的人工验收、独立目录切换/回退协议，以及跨命令冻结研究会话，见[恢复验收与研究会话](恢复验收与研究会话.md)。离线恢复不表示最新抓取成功，也不自动切换真实项目。

离线演示会生成标记为 `SYNTHETIC_DEMO_NOT_MARKET_DATA` 的合成数据。它只用于确认
程序、图表和指标可以运行，绝不是真实行情。
