# 第七课：先认清数据，再认清账户

前六课回答的是“策略在历史数据上表现怎样”。第七课补上两个更基础的问题：我们究竟使用了
哪一份数据，以及账户里的钱和份额是否真的对得上。

## 一、为什么需要数据集ID

同名的 `sh_510300.parquet` 可能在明天被更新。如果只记文件名，以后无法知道报告使用的是
今天的文件还是明天的文件。`run_data_health.cmd` 会读取整理数据并记录：

- 文件SHA-256：文件内容改变一个字节，指纹通常就会改变；
- 数据集ID：由所有整理文件的路径、指纹、行数和标的组合生成；
- 行数、开始日、结束日、字段结构、来源、复权方式和成交量单位；
- 相对检查日的滞后交易日、交易日历快照 SHA-256 与公告来源，以及最近一次数据源失败信息。

`generated_at` 每次运行会改变，但数据文件没有改变时，`dataset_id` 保持不变。因此实验记录
应引用数据集ID，而不是只写“使用最新数据”。

## 二、“warning”不等于可以忽略

健康状态分为 `pass`、`warning` 和 `error`。不复权、数据陈旧、混合来源或上游更新失败都会
形成提醒。提醒不一定说明数据不可用，但报告使用者必须知道它可能怎样影响结论。

陈旧度使用仓库内的 `config/sse_trading_calendar.json`。它保存 2022–2026 年上交所公告的工作日
休市日期、覆盖范围、来源链接和 SHA-256；报告会把这份快照一起写下来。覆盖范围内，春节和
国庆等长假不会被误数成“数据陈旧”。覆盖范围外会退回周一至周五的保守估算，并生成
`calendar_snapshot_out_of_range` 提醒；前向模拟盘会停止，而不是把近似结果当作精确交易日。

联网失败也不会删除已有文件；系统会继续展示旧数据，并明确报告失败，绝不把旧数据说成已经
更新成功。

## 三、百分比净值不等于真实账户

早期回测用0和1表示空仓与满仓，适合学习策略逻辑，但没有回答“10万元能买多少份”。账户
账本从现金出发，每个交易日按下面顺序记录：

1. 前一交易日收盘后得到信号；
2. 下一交易日开盘按假设滑点形成成交价；
3. 买入时只能购买 `lot_size` 的整数倍，并预留佣金；
4. 卖出时扣除佣金和假设卖出税费；
5. 用剩余现金加持仓按下一开盘估值，形成当日账户权益。

每笔交易都保留成交日、信号日、数量、名义金额、佣金、卖出税费和成交后现金。程序还会逐行
检查：信号是否早于成交、现金和份额是否为负、份额是否整手、现金流和权益能否重新计算、数值
是否有限且权益是否为正。任一检查失败都会中止正式报告。

## 四、为什么指数被拒绝

`sh.000300` 是指数，不是可以直接买入的证券。它仍可作为研究基准，但不能被账户账本假装成
可成交资产。默认账户实验使用配置中标为ETF的 `sh.510300`；将来加入股票时也必须先在配置中
明确其种类。

## 五、费用都是假设，不是报价

默认的3 bps佣金、5元最低佣金、0 bps卖出税费和2 bps滑点只是一组教学参数。不同账户、
证券类别、时间和交易渠道可能不同。除非引用了明确适用且生效的规则，否则报告只能称其为
“假设情景”。

## 六、还缺什么

当前账本没有单独处理ETF分红、除权现金流、部分成交、订单排队、市场冲击和申购赎回。不复权
价格加上缺失的分红现金流，会低估长期含分红总回报。因此这一课的目标是建立可核对的研究
账本，不是产生可直接下单的策略。

建议操作顺序：先运行 `run_data_health.cmd`，记录数据集ID和提醒；再运行 `run_account.cmd`，
查看HTML和逐笔CSV；最后对照 `experiments/006_data_and_account_ledger.md`，理解为什么亏损和落后
基准的结果也必须保留。
