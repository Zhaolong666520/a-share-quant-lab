# P2.2ad：日线日期故障校验

## 范围

对已加载日线表格的 `trade_date` 做失败安全的校验，不修改原始快照、交易模型或已发布数据。先用合成数据复现，再做最小修复。

## 任务

1. 字符串、混合类型和不可解析日期不使校验器抛出未分类异常；无效值返回 `invalid_date`。数值型日期不能被解释为 1970 年附近的时间戳。
2. 非零时间的日线日期返回独立错误；比较和重复主键采用解析后的日期，避免同一天不同表示绕过校验。
3. CLI `validate` 对正式整理文件中的畸形日期继续输出结构化失败、非零退出，且不暴露底层数据内容。
4. 定向与完整 pytest、Ruff、mypy、Markdown 链接和差异检查通过；全部使用临时项目与合成行情。

## 非目标

不联网抓取行情，不更改真实数据，不重新解释已有研究结果，也不自动合并或发布。

## 实施记录

原校验器在字符串交易日期上计算间隔时会抛 `TypeError`；含时分秒的日线记录会漏检；数值 `0` 会被解释为 1970 年午夜；CLI 与清单的预转换又会把混合格式时间误判为无法解析。现统一先按混合格式解析日期并拒绝数值日期，校验无效日期、非零时间、解析后的主键重复及排序；CLI 不再提前转换，清单复用同一解析器用于日期范围统计，不能把无效数值显示成 1970 年。畸形值只进入固定错误码，不进入命令输出。

## 验证结果

临时 Parquet 和合成日线覆盖字符串、无效日期、非零时间、混合格式同日重复及数值型日期；单元、`validate` 命令与清单状态均有回归。清单对全数值日期报告空起止日期，不显示伪造的 1970 年。完整 `pytest -q`、Ruff、mypy、76 份 Markdown 链接及 `git diff --check` 通过；1 项 Windows 符号链接权限测试跳过。未联网或修改正式行情。
