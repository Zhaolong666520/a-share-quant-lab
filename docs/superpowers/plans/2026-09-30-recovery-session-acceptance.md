范围：P1.2b.2b.3 与 P1.2b.2c。仅本地实现，不自动选择真实原始快照，不覆盖当前项目，不发布。

## 验收契约

- 恢复候选必须通过既有原材料、原始行情、curated、数据库逐行一致性和账本审计。
- 人工确认完整 candidate_id；目标必须是全新且与项目、材料、候选完全独立的目录。
- 恢复状态先保持 updating；完成独立复制、健康检查、账本无损验收及凭据后，最后发布 completed。
- 来源、候选及原隔离标记保留；离线恢复摘要必须显式标识上游警告，不伪装实时抓取成功。
- 手动设置 FINANCE_LAB_ROOT 完成切换；回退只恢复环境变量，原项目不删除。
- 研究会话复制 config、data 与更新摘要，冻结整份数据集 ID 和文件指纹；输出报告不属于冻结输入。
- 每个会话命令前后核验，并在整个命令期间持有行情锁；禁止快照行情和模拟账本写入。
- 验证命令不得创建不存在的项目；不承诺抵抗恶意用户同时修改文件和凭据，不等于操作系统只读挂载。

## 用户要求复查后的补充验收

使用 code-review 的正确性与回归优先流程，对实现重新审查，先增加测试复现，再修复以下三处缺口：

1. 旧项目仅有 config 与整理行情时，冻结副本缺少 raw/outputs，后续命令的 get_paths 自动补建目录使指纹变化。现在在独立副本发布凭据之前补齐目录，来源不变。
2. 命令前后只单独核验凭据，无法拒绝执行期间替换成另一份可通过核验的凭据。现在两次核验结果都必须与最初的凭据完全一致。
3. 单日恢复借用次日满足状态的非空范围约束时，错误复用了次日作为摘要日期。现在状态范围上界与实际最后交易日分开保存，摘要不虚增日期。

三项新增回归先全部失败，再全部通过；专项测试合计 21 passed。
