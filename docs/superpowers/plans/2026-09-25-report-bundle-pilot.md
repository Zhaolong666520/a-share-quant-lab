# P2.2j 多文件报告完整性标记试点

依据：[历史报告文本原子替换](2026-09-25-research-report-atomic-text.md)和[图表/CSV 原子替换](2026-09-25-research-report-atomic-assets.md)。现有报告文件名被本地页面和用户文档直接引用，本批不改为整目录切换，而是先让基础回测报告在所有成员写完后发布原子完成标记，并提供只读完整性核验。

1. 用合成回测和临时项目写失败测试：完整报告有包含 HTML、PNG、JSON 哈希的标记且可核验；改动成员文件、成员缺失或重跑时中途失败必须核验不通过，不把旧标记当作新报告完成。
2. 实现只接受同目录常规文件名的标记生成/核验工具，最后写标记，保留现有三文件路径与返回值。标记是完整性证据，不是跨文件原子提交，也不证明策略有效。
3. 先接入基础回测报告；其他七类报告、CLI 核验入口和更强的整组版本切换留给后续批次。运行定向、全量和静态检查，记录结果。
