# P2.2x：`fetch` 行情更新中断诊断

## 边界

已有的来源失败路径会把 `failed` 或 `partial_sources` 写入更新摘要并返回非零。本批只处理 `fetch` 在更新流程中遇到 `OSError` 或行情批次状态错误、尚未正常返回摘要的场景；不改变数据源选择、行情写入与恢复机制，也不联网测试。

## 失败契约

- 命令返回码 1，输出单个安全 JSON：`error_code=market_update_interrupted`、`stage=update_market_data`、`data_committed=null`、`summary_state=unknown`。
- 尽可能只读附带持久化批次的状态、隔离标志和阶段；若诊断本身不可用，则标为 `unknown`，不泄露底层异常或猜测提交情况。
- 更新可能已发布部分行情但摘要仍是旧版。提示保留行情、原始快照和状态文件，先运行 `data-update-status` 审计，再决定恢复或重试；不能把旧摘要当作本次成功结果。
- 已经正常返回的全失败或部分来源失败仍沿用既有退出码和摘要语义。

## 验证

在临时项目、合成行情上模拟新行情写入后摘要写入异常。CLI 返回安全非零诊断；新整理行情确已出现，旧摘要字节保持不变，持久化批次为 `failed` 且隔离读取。定向测试和完整 pytest 通过（仅一个 Windows 符号链接权限相关测试跳过）；Ruff、mypy、Markdown 链接及 `git diff --check` 通过。未调用真实行情接口。

## 后续

`all` 的行情更新中断路径和更早阶段的状态写入故障可分别验收；不能把这里的未知提交状态套用到已确认完成的 `all` 报告失败路径。
