# P2.2aa：每日模拟盘失败留证与推进门禁

## 边界

`paper-daily` 依次更新行情、校验数据健康、运行或初始化教学模拟盘，最后写不可变运行归档和 latest 状态。本批不改变行情源、交易模型或账本事件，只收紧“能否推进到下一步”的条件，并保护失败留证中的私有异常信息。

## 本批改进

1. 失败归档与 CLI 不再写入底层异常原文；保留异常类型、稳定错误码和按失败步骤划分的安全说明。
2. 归档中显式记录 `market_data_committed`：更新正常返回且有成功标的时为 `true`，正常返回但无成功标的时为 `false`，更新抛异常或返回未知状态时为 `null`。`null` 不可解释为未写入。
3. 不同阶段分别提示 `data-update-status`、数据健康核对或 `paper-status`，避免更新中断后盲目重跑或重置账本。
4. 只有更新结果明确为 `status=success`、成功标的数为正整数且 `failed_sources=0` 时，才允许进入数据健康和模拟盘步骤；缺失/未知状态、缺失或非零失败来源数、浮点数、布尔值和零标的均停止。
5. 状态归档本身写入失败时，继续传递未知的行情/账本提交情况，不把中断误报为未发生。README 同步修正“每次失败都会有归档”的过度承诺。

## 验证

临时项目与合成动作覆盖行情、健康、账本三处私有异常，检查归档/latest/CLI 无底层路径或令牌；另测 DuckDB 更新中断后下游步骤未运行、缺失/未知更新状态及非法计数不会推进、状态归档写入失败保持 `null` 提交状态。定向测试和完整 pytest 通过（仅一个 Windows 符号链接权限相关测试跳过）；Ruff、mypy、Markdown 链接及 `git diff --check` 通过。未联网获取行情或操作真实资金。

## 限制

若进程被强制终止或磁盘故障阻止状态落盘，不能保证一定留有新的归档；仍需人工核对行情批次、账本事件和现有状态文件。
