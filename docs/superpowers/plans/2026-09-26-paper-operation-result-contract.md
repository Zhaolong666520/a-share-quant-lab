# P2.2ac：每日模拟盘操作结果契约

## 边界

`paper-daily` 的行情、健康和账本步骤由已有实现负责。本批只核验运行或初始化步骤返回的结果，防止错误状态被归档为每日运行成功；不改变成交、策略或真实资金边界。

## 实施

1. `paper_run` 只接受有处理日期的 `processed` 或无处理日期的 `no-op`；`paper_init` 只接受恰有一个处理日期的 `initialized`。
2. 处理日期须为严格递增的日期元组，且不能晚于本次 `as_of_date`。
3. 仅通过核验的候选结果才进入成功归档。结果不一致时记为对应步骤失败，账本提交状态保持未知，提示先用 `paper-status` 审计，不能把坏结果误认作未记账。
4. 运行或初始化步骤声称成功时须返回报告路径；缺少路径不能把每日任务归档为成功。这只核对返回契约，不替代已有报告写入校验。
5. 数据健康步骤也须返回报告路径；缺少路径时停在 `data_health`，不推进模拟盘。路径类型核验不等同于独立验证报告文件内容。

## 验证

使用合成动作先复现 8 种错误状态/日期、3 种缺少模拟报告路径和 1 种缺少健康报告路径的误报成功，再核对修复后均非零退出并写入失败归档；正常 `no-op` 重跑仍成功且不宣称新增账本提交。完整 `pytest -q`、Ruff、mypy 和 `git diff --check` 通过；1 项 Windows 符号链接权限测试跳过。未联网获取行情，也未操作真实资金。

## 限制

返回结果异常只说明自动化无法确认步骤完成情况；如果底层账本已写入，仍须审计事件后再决定是否重跑。云端和其他操作系统尚未验证。
