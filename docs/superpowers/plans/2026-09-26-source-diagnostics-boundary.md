# P2.2ab：数据源诊断写入边界

## 问题与边界

`fetch`/`all` 的来源记录会进入 `update_summary.json`、CLI 输出和下游清单/报告。此前意外 `ValueError` 的原文，以及来源返回的任意 `source_diagnostics` 属性，可能把外部 URL、令牌、路径或伪造计数写入这些产物。本批只约束新生成的来源诊断，不改原始快照和已有历史摘要。

## 实施

1. `DataSourceError` 和 `ValueError` 不再把异常原文写入 `source_errors`。来源名及白名单阶段组成稳定说明；未知阶段归为 `unknown`。
2. 请求/解析与已取得表格后的校验分别标记 `request` 和 `validation`，保留可排查的失败阶段，但不暴露外部异常正文。
3. 来源行数诊断必须具有约定字段、非负整数、与表格行数一致的接收/接受/拒绝关系，以及仅允许 `nontrading` 的拒绝原因；无诊断属性时沿用已验证表格的零拒绝默认值，伪造或畸形属性则拒绝该来源。
4. 异常对象中的行数计数若不满足非负整数与守恒关系，归零而不写入任意文本或无效数值。

## 验证

临时项目和合成表格分别注入带私有 URL 的解析异常、任意阶段的来源异常、私有拒绝原因和畸形异常计数；确认 CLI 与新摘要无私有字符串，失败状态和阶段仍可读，原始快照不因畸形诊断而发布。真实 BaoStock 过滤计数与既有来源契约测试继续通过。完整 `pytest -q`、`ruff check .`、`mypy src`、Markdown 链接检查及 `git diff --check` 均通过；测试中有 1 项因 Windows 符号链接权限跳过。未联网获取行情。

## 限制

此改动不重写过去已生成的摘要；手工导入或旧版本产物中的自由文本仍应按不可信内容处理。极端进程中断与跨平台故障另行验证。
