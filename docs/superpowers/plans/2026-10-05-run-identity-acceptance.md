## 发现、修复与再次验证

- 新身份元数据不合法时，原末尾校验可能抛错而未保存失败归档：先补失败测试，再将元数据验证前移，只传播已接受事实；健康、操作、专用异常返回均覆盖。
- 新字段曾破坏旧错误构造器，收据格式策略曾误收紧旧存储opaque/空输入：恢复默认参数兼容、分离存储事实与归档字符规则，并补真实事务回归。
- 独立审查发现已审计账本整组缺失时，snapshot先抛审计异常，导致非空引用被笼统记为unavailable：同一只读事务内先检查组合存在性；明确非空complete/partial改为mismatch，空no-op仍unavailable，unknown仍not_available。实施者RED/GREEN、独立复审和最终交叉各自复验通过。
- 初次全量1057 passed / 4 skipped / 1 failed，失败为私有实施brief复制计划后两处相对Markdown链接错位；同时mypy发现局部状态类型过窄。分别修复链接和局部注解后重跑全部，不扩大旧模型状态集合。
- 独立驱动初次两次失败分别为市场批次ID夹具格式错误、误把业务no-op当成数据库物理只读；修正驱动而非降低状态CLI禁写要求。失败根、traceback和后续各轮结果均保留，不把夹具错误当作功能RED。
