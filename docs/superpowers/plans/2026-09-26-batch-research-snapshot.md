# P1.2b.2c.2：批量研究命令的统一行情快照

## 风险与范围

单份报告已从读取到发布持有行情锁，但七个 `*-all` 批量研究命令在标的之间释放锁，可能混用两代行情。`all` 在数据更新成功后逐标的生成报告，也有同类空档。本批仅保证每一次 CLI 批次运行期间，协作式行情更新不能插入；不为跨命令研究会话创建持久快照。

## 任务

1. 用双标的合成批次复现：首份报告后、第二份报告前，竞争线程可取得行情锁。
2. 七个 `*-all` 研究命令和 `all` 从预检/更新到批次报告输出持有同一项目级可重入锁。单份报告继续使用上批的嵌套锁。
3. 抢锁失败须给出安全的结构化非零诊断，明确本次没有启动报告批次；异常和提前返回均释放锁。
4. 用临时项目验证七个命令、`all`、锁竞争和失败释放，再跑完整测试、Ruff、mypy、链接和差异检查。

## 限制

长批次会阻止协作式行情更新；不会阻止绕过项目锁的外部写入。一次命令内的批次一致性不等于跨多条命令或长期研究会话的快照绑定。

## 验证结果

先以两标的合成批次复现七个研究命令和 `all` 在报告之间均能被竞争者取得行情锁。实施后，七个研究批次、`all` 的更新与两份报告步骤均拒绝竞争线程；外部占锁时两类命令在执行前给出安全、结构化、非零诊断且不启动更新或报告；失败后可重新取得锁。11 项定向测试与完整 `pytest -q` 通过（1 项 Windows 符号链接权限测试跳过）；Ruff、mypy、78 份 Markdown 链接及 `git diff --check` 通过。未联网抓行情，未修改正式数据。
