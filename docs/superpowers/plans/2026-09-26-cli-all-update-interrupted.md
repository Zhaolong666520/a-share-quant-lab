# P2.2y：`all` 行情更新中断诊断

## 边界

`all` 先更新行情，确认更新完整后才逐标的生成回测报告。已有分支分别处理全部来源失败、部分来源失败，以及行情已成功提交后报告写入失败。本批只处理行情更新流程抛出 `OSError` 或批次状态错误、尚未正常返回摘要的情况。

## 失败契约

- 与 `fetch` 共用安全的 `market_update_interrupted` 诊断：返回码 1，`data_committed=null`、`summary_state=unknown`；尽可能只读报告批次状态、隔离标志和阶段。
- 不进入任何回测报告步骤，不打印行情或报告成功提示。已写入的行情和旧摘要均须保留；先运行 `data-update-status` 核对批次，再决定恢复或重试。
- 不能把此分支解释为已确认提交的 `all` 报告失败，也不能声称行情已回滚。

## 验证

在临时项目、合成行情上注入新行情发布后的摘要写入异常。`fetch` 与 `all` 均返回单个安全失败 JSON；`all` 的回测函数未调用。新整理行情确已出现、旧摘要字节不变，持久化批次为 `failed` 且阻止后续读取。定向测试和完整 pytest 通过（仅一个 Windows 符号链接权限相关测试跳过）；Ruff、mypy、Markdown 链接及 `git diff --check` 通过。未调用真实行情接口。

## 后续

更早阶段的状态文件写入故障、数据库同步中断及每日自动化对行情中断的解释仍需独立验收。
