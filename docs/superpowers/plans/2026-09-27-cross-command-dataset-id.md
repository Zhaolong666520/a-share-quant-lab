# P1.2b.2c.3：跨命令数据集身份门禁

## 目标与边界

已有单报告和单批次行情锁，但两次独立 CLI 调用之间仍可能更新行情。增加显式的 `--expected-dataset-id` 门禁：研究者先运行 `manifest` 保存完整数据集 ID，后续只读研究命令每次在同一行情锁内核验 ID 并生成报告。默认命令行为不变；`all` 会更新行情，不接受该预期 ID。此门禁不冻结跨命令数据，也不阻止绕过项目锁的外部写入。

## 任务

1. 在临时合成数据上先写回归测试：正确 ID 可生成报告；换代、缺数据、清单错误、非法 ID 都不得开始报告；单命令核验至报告完成不得被协作式更新插入；批量命令沿用统一锁。
2. 对 8 个单标的和 7 个批量只读研究命令增加可选参数。严格校验 64 位十六进制 ID；在锁内生成清单，拒绝不匹配或健康状态为 `error` 的数据，输出不泄露本地异常/路径的结构化非零诊断。
3. README 说明先记录 ID、再绑定多条命令，以及门禁的限制；更新总设计状态。
4. 跑定向/完整测试、Ruff、mypy、Markdown 链接和差异检查；只用合成数据，不联网或修改正式行情。

## 本地验证结果

先确认未实现时带预期 ID 的命令被参数解析拒绝。实施后，15 个只读研究命令均接受完整 ID，`all` 明确不接受；正确 ID 下单份与批量报告可运行，行情换代、缺文件、健康状态错误、内部清单故障、锁占用都会在报告开始前非零退出。额外以离线合成数据生成真实回测并通过报告完成标记核验；内部错误路径不会泄露到 CLI 诊断。定向测试、完整 `pytest -q`（1 项 Windows 符号链接权限跳过）、Ruff、mypy（46 个源文件）、79 份 Markdown 链接及 `git diff --check` 通过。未联网、未修改正式行情、未推送或合并。
