# P2.1 数据源离线契约设计

日期：2026-09-25。状态：已按本设计实施并通过本地离线测试；真实联网接口尚未验证。

## 为什么现在做

正式项目只读检查显示：最近一批行情状态为 `completed`、未被隔离；两份整理文件各 2,120 行且基础校验没有错误或警告。因此当前无需真实恢复或目录切换。只读数据清单仍带有历史 AKShare 请求失败记录，且现有 `sources.py` 会在转换后 `dropna`，可能在有异常行时静默缩小样本。下一阶段优先把数据源输入契约和失败留证做牢。这里记录的是本机 2026-09-25 的观察，不代表以后一直健康，也不推断当前网络可用。

## 边界

本阶段只使用本地合成/固定响应样本；不调用真实行情接口，不修改 `data/`、模拟账本或计划任务，不承诺解决上游网络故障。测试替身只放在 AKShare/BaoStock 的外部调用边界，转换与流水线仍走真实项目代码。

## 接口契约

1. 每个数据源报告收到、接受、拒绝的行数，三者满足 `收到 = 接受 + 拒绝`。空响应、缺少字段、坏日期、非数值价格/成交量、重复日期、非目标标的或超出请求日期区间不能变为“完整成功”。
2. 若收到非交易状态记录，明确记录过滤理由与行数；如其余行可用，仍需在更新摘要展示该过滤，不将行数损失隐藏在 `dropna` 中。不同数据源的单位和复权口径必须保留，不混用成交量。
3. 上游抛错、超时、登录或查询失败要有稳定的阶段和错误类别；默认公开诊断不输出完整请求 URL、代理地址或凭证。BaoStock 已成功登录后，不论查询或转换是否失败都必须调用退出；登录失败不能假称已退出。
4. 只要某源本次未交付完整可验证的数据，该源标记失败。若另一源成功，可保留其行情，但总体结果必须显式包含失败源、成功源、实际日期范围与行数。两源都失败时不得发布新的整理行情；已有旧数据也不能掩盖本次失败。
5. 样本的交易日空档不凭日历自动补行。历史数据是否足量、上游接口是否稳定、现实费率与可交易性仍是独立问题。

## 验收矩阵

- AKShare 指数与 ETF：正常响应、空响应、缺列、坏日期、坏价格、坏成交量、重复日期、边界外日期、调用异常。
- BaoStock：登录失败、查询失败、迭代异常、缺列、非交易状态、数值异常、退出异常及退出恰好一次。
- 流水线：主源失败而备用源成功、两源失败、部分行被拒绝、摘要写入异常；逐一检查未发生无声补齐、错误码和行数守恒。
- 定向测试和全量回归、Ruff、mypy、Markdown 链接与差异检查通过。可选联网检查单独标注，不能被离线测试代替。

## 非目标及后续

不新增第三方数据商、不购买历史数据、不自动恢复正式项目。P1.2b.2b.3 的人工切换协议继续保留为故障恢复能力，但必须有实际完整材料包、候选复核通过和人类明确批准才执行；健康项目不为完成流程而切换。
