# BaoStock 分页完成保护

本实现针对SDK 0.9.3的已验证行为：满2000行页耗尽后，如果下一页返回None或空响应，SDK可能返回False而保留错误码0。仅凭循环结束或错误码0，不能把已收到的部分行判为完整行情。

采集器在构建DataFrame前检查结束错误码、页行数、已消费游标、页号和页大小，并要求累计收到行数等于“(页号－1)×2000＋末页行数”。仍停在满页、跳页/回退或状态缺失/异常时，抛出iteration阶段的DataSourceError；收到N行而整次响应不接纳时，记录received=N、accepted=0、rejected=N。已确认的空尾页、短尾页及该版本明确支持的超2000行整包，继续通过原有标的、日期、非交易行和数值校验。

SDK内部终态不是跨版本的稳定契约。因此依赖声明与运行检查均限定0.9.3；版本未知、无法读取或未验证时，在登录前以import阶段失败。此变更没有安装或升级环境；未来支持其它版本须先审阅实现及离线验证，不可仅放宽版本号。

异常使用固定原因与受控数值，不包含SDK响应或原始异常文本。直接调用能查看分页原因/终态；更新摘要沿用原有失败阶段与行数契约，不新增内部SDK结构字段。登出异常保留原先分页失败优先级。

不完整BaoStock响应不会返回DataFrame，也不会进入该源有效行情快照。腾讯等其它成功来源仍可保存自身市场数据；不能将失败处理称为整体市场更新回滚。只要有必需来源失败，每日流程就停在market_data_update，记录失败、非零退出码并停止推进模拟账本。

验证使用真实安装SDK的ResultData，替换网络传输及登录/查询/登出边界；全部行情夹具为合成数据。覆盖满页断流、空响应、非法页号、错误响应、正常空/短尾页、整包及未知元数据，并验证真实适配器经过隔离更新流程后使每日任务失败且原paper_*账本保持不变。

此保护不改变正式来源请求窗口、阈值或计划任务。接入状态和按日期验收证据见[项目当前状态](项目当前状态.md)；离线验证不进行真实来源查询。离线分页保护通过不代表所有市场日期完整，也不代表正式历史覆盖率已改善。
