# 恢复验收与冻结研究会话

这两项属于离线研究基础设施，不连接券商，不保证策略收益。

## 一、恢复候选验收与人工切换

先按照既有恢复流程生成材料和候选。必须明确选择可信原始快照；本命令不代替人工判断数据来源。
`data-recovery-candidate-verify` 输出完整 `candidate_id`，确认后执行：

```powershell
.venv\Scripts\finance-lab.exe data-recovery-candidate-verify --bundle C:\quant\bundle --candidate C:\quant\candidate
.venv\Scripts\finance-lab.exe data-recovery-activate --bundle C:\quant\bundle --candidate C:\quant\candidate --destination C:\quant\recovered --confirm-candidate-id 完整candidate_id
.venv\Scripts\finance-lab.exe data-recovery-acceptance-verify --root C:\quant\recovered
```

路径是示例，须替换成实际目录；目标必须不存在，且其父目录已经存在。材料、候选和原项目不得互相嵌套。
验收检查独立副本的文件指纹、行情数据库与 Parquet 一致性、模拟账本审计及五张账本表指纹、数据集健康。
验收凭据写完之后才发布完成状态；中断保留目标目录并保持隔离，不应删除状态文件继续使用。重试需使用另一个新目录。
原项目、原材料、候选及其隔离标记不改变；新项目的 `recovery_evidence` 保存候选报告、选择清单和原状态标记。

只有复核成功且确认来源与日期范围符合预期之后，才在自己的 PowerShell 中切换：

```powershell
$previousFinanceRoot = $env:FINANCE_LAB_ROOT
$env:FINANCE_LAB_ROOT = 'C:\quant\recovered'
.venv\Scripts\finance-lab.exe data-update-status
.venv\Scripts\finance-lab.exe dataset-check --expected-dataset-id 验收输出的完整dataset_id
```

这只改变当前终端的项目数据根，不修改 Git、系统环境变量或自动任务配置。
如需回退，恢复 `$env:FINANCE_LAB_ROOT = $previousFinanceRoot`；原项目可能仍处于隔离状态，回退不等于修复它。
定时任务不会因此自动切换，必须单独核对它的工作目录及环境。

恢复摘要明确标为离线恢复和 `partial_sources`，历史快照不代表今日行情，不能当作最新抓取成功。
正常更新或模拟账本推进后，验收复核会指出目录已改变；这是旧凭据不再适用于新状态，不应覆盖旧证据。

## 二、跨命令冻结研究会话

一次创建会话，后续所有研究命令使用同一个 `--session`：

```powershell
.venv\Scripts\finance-lab.exe research-session-create --destination C:\quant\research-session
.venv\Scripts\finance-lab.exe research-session-verify --session C:\quant\research-session
.venv\Scripts\finance-lab.exe backtest --symbol sh.000300 --session C:\quant\research-session
.venv\Scripts\finance-lab.exe experiment --symbol sh.000300 --session C:\quant\research-session
.venv\Scripts\finance-lab.exe compare-all --session C:\quant\research-session
```

目标同样需要新建独立目录。创建时可添加 `--expected-dataset-id` 确认来源版本。
冻结包含 `config/`、`data/` 和 `outputs/update_summary.json`，独立复制而非硬链接。
旧项目缺少 raw/outputs 目录时，只在独立副本中补齐必要目录，再发布冻结凭据，不修改来源。
后续正式数据更新不会改变会话；每条命令自动绑定会话数据集 ID，命令前后校验冻结文件与配置并持有行情锁。
命令前后必须是同一份会话凭据；即使替换后的凭据能够单独通过校验，也不能将这次执行视为可信结果。
显式传入不同的 `--expected-dataset-id` 会被拒绝，不能覆盖会话 ID。

支持的 15 个研究命令为：`backtest`、`account`、`account-all`、`experiment`、`experiment-all`、
`walk-forward`、`walk-forward-all`、`cost-stress`、`cost-stress-all`、`parameter-test`、
`parameter-test-all`、`execution-test`、`execution-test-all`、`compare`、`compare-all`。

报告写入会话 `snapshot/outputs/`，不覆盖正式项目报告。报告输出不计入冻结输入，生成报告不会使会话失效。
直接将 `FINANCE_LAB_ROOT` 指向会话 `snapshot/` 时，CLI 也会自动执行会话校验。
会话禁止 `init`、`fetch`、`all`、`paper-init`、`paper-run`、`paper-daily`；行情写入和模拟账本推进 API 同样阻断。
这不是操作系统只读挂载：外部程序仍可能修改文件，但下一次校验会拒绝继续。

要使用新的正式行情或改变参数配置，请创建新会话，不要修改原会话的文件或凭据。
凭据与文件 SHA-256 用于防止意外变化，不是签名系统，也不抵抗恶意用户同时改写凭据和数据。

## 三、每日模拟运行的区间验收

恢复副本的离线验收与随后运行的验收是两件事。获批使用实际根目录后，在推进模拟账本之前，
先捕获已有五张账本表与该账户组的归档基线。证据目录应位于业务根之外，且父目录已经存在：

```powershell
$baselineJson = & .\.venv\Scripts\python.exe -B -m finance_lab.paper_run_acceptance capture --root C:\quant\recovered --portfolio default
if ($LASTEXITCODE -ne 0) { throw '基线捕获失败，先检查输出诊断' }
[System.IO.File]::WriteAllText('C:\quant\evidence\before.json', ($baselineJson -join "`n"), [System.Text.UTF8Encoding]::new($false))
```

上述路径均为示例；另选新的证据文件，保留每批基线，不覆盖过去的证据。UTF-8 无 BOM 可避免
PowerShell 5 默认输出编码与严格 JSON 不兼容。基线自哈希仅检测意外改动，不是签名认证。

随后按既有每日模拟运行流程保存正常处理和同一 `as_of_date` 的重复运行归档，再将基线之后
**全部新归档**中的 32 位 `attempt_id` 按发生顺序传入；超过两次时逐条增加参数：

```powershell
.\.venv\Scripts\python.exe -B -m finance_lab.paper_run_acceptance verify --root C:\quant\recovered --portfolio default --baseline C:\quant\evidence\before.json --attempt-id 第一次完整attempt_id --attempt-id 末次完整attempt_id
```

capture/verify 只读，不执行每日运行、不补建目录/锁、不写证据文件或报告。verify 检查：

- 旧归档字节、账户/结构元数据、全部旧 run/event 行没有被删除或改写；允许有新提交的账户更新 state。
- 每个新归档完整且选择无遗漏，收据精确对应实际账本行，全部新增提交均有唯一归属。
- 所有新尝试成功，并在正常 processed 后以同日期 complete 空收据的 no-op 收尾。

只有这些检查全部成立，才返回该记录区间的 `passed`。未归档提交、坏归档、失败/部分完成或
unknown 不会被视为完整成功；读取/审计失败、WAL、危险路径或观察中输入变化拒绝通过。
读取根不存在/不安全属于证据错误；非法参数或基线协议错误退出 `2`，其他不通过退出 `1`。

这是 `recorded_automation_and_ledger_interval` 范围的非原子观察，不能证明实际进程退出码、
持续调度、当前行情健康或报告文件完整性。基线之后若继续运行，应保存新的基线开始新批次；
不要用旧区间选择子集冒充完整验收。[本批计划](superpowers/plans/2026-10-06-run-acceptance.md)
及[交付记录](superpowers/plans/2026-10-06-run-acceptance-report.md)将隔离合成演练与真实持续运行分别列示。

## 四、代码目录与运行数据目录分离

仅在独立恢复目录通过验收、来源和模拟运行门禁后使用。以下为通用示例，不表示本机已切换：

```powershell
# 当前终端的一次模拟运行；代码和venv仍来自维护仓库
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\scripts\run_paper_daily.ps1 -DataRoot 'C:\quant\recovered'

# 明确授权安装/替换任务之后才执行；不要用它覆盖尚未核对的既有任务
.\scripts\install_paper_daily_task.ps1 -DataRoot 'C:\quant\recovered'
```

DataRoot必须是已经存在的普通文件系统目录，不能使用`..`、异常字符、链接或重解析点祖先。
相对路径按调用位置解析成绝对路径。显式DataRoot优先于进程FINANCE_LAB_ROOT；
不传DataRoot时，runner优先沿用进程变量，否则使用维护仓库根。空的显式参数/环境根不会静默回退。
代码与Python环境仍从脚本所在维护仓库获取，日志写入所选数据根的`outputs/paper_automation_logs/`。
脚本结束恢复其调用进程之前的根变量和工作目录；不修改用户或系统环境变量。
installer仅显式参数时在TaskAction固定数据根，不传时保留原参数语义；运行脚本同样保留旧调用兼容。

回退需恢复之前保存的TaskAction和启用状态，保持触发器、身份和其他设置。
当前终端变量回退不会修改计划任务，任务配置回退也不修复原目录的隔离标记。
不要删除故障候选或手工更改更新状态来绕过门禁。
本机此次未接入新根，具体已验证与未通过的范围见[10月8日处理记录](superpowers/plans/2026-10-08-runtime-recovery-report.md)。
