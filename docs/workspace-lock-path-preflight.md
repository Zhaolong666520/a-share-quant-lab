# 研究会话与恢复验收的锁路径检查

日期：2026-11-06。阶段：P1数据与账本可靠性。本文描述隔离候选；未接入正在进行五日观察的正式代码，不属于发布。

## 修复的问题

创建研究会话或核验恢复目录时，如果`data`目录或即将使用的锁文件是Junction/符号链接，旧流程可能先touch锁文件，再由后续清单校验拒绝路径。外部目标可能新增锁文件、空文件被写入NUL，或目录修改时间改变。核验研究会话已经检查`data`目录，但遗漏了`market_data.lock`叶路径。

CLI的`research-session-create`还会提前解析环境变量根目录，消除原路径中的链接信息，使后续安全检查无法识别原始路径。这个问题要求输入中已经存在不安全链接；本批没有发现正式任务实际遭遇该情况，也不把它解释为11月4日原生崩溃的原因。

## 当前行为

- `create_session`和`verify_activation`在取得任何锁之前，使用既有`_safe_path`分别检查两条锁路径及其祖先。
- `verify_session`在取得行情锁之前检查该锁路径，保持原有数据目录检查。
- CLI保留选择的原始根路径，交给入口安全检查；其他命令的根选择不变。
- 原有锁内WAL、清单、数据集身份及复制前后复核继续执行。普通缺失锁仍允许创建，通用锁实现及账本格式不变。
