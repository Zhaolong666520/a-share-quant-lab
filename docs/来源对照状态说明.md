# 来源对照状态说明

运行状态诊断中的`market.source_comparison_warnings`（runtime输出在`recorded_status.market`下）将抓取结果和来源对照分别展示。更新成功不等于历史独立对照通过；来源warning仍保留attention及非零诊断退出码。

`coverage_ratio`保持摘要原值，缺失为null。`coverage_scope=all_returned_rows`表示共同日期行数除以两侧规范化后参与比较的总行数较大值，未裁剪为共同请求窗口。它不指供应商筛选、去重前的原始响应行数，也不证明供应商完整返回了请求历史；95%门槛和价格比较规则不变。

`request_window_context`只接受已知来源组合、有效且严格为YYYY-MM-DD的起止日，以及与主源身份一致的角色。`primary`和`reference`展示来源和请求起止日。`relation`含义如下：

| relation | 含义 |
|---|---|
| same | 两侧请求范围相同，不能据此认定逐日完整 |
| shorter | 对照请求区间是主源的真子区间 |
| different | 其他不同范围，包括交叉、对照更宽或不相交 |
| unknown | 请求元数据缺失、格式错误、身份/角色不一致或来源组合未知 |

请求元数据不可用时仅补充上下文为unknown，primary/reference为null，可靠的原比较warning及覆盖率继续显示。不回显供应商消息或任意额外字段。若读取期间摘要发生变化，整份旧比较及其请求上下文按既有机制撤销。

例如主源返回2134条、对照返回192条且共同192条时，完整返回历史覆盖为192/2134，约9%。若对照请求范围较短，会额外解释短窗口；不能从请求日期和汇总条数推算窗口内“192/192”或把warning改成pass。该诊断没有重新读取逐日快照，因此窗口内逐日覆盖仍未计算。

本项只改善状态解释，不改变抓取请求、数据源、策略、阈值、调度、业务快照或账本，也不消除历史来源缺口。
