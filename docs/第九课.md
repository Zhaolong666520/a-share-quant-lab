# 第九课：前向模拟盘与事件账本

这一课把固定规则放进**本地前向模拟盘**：它不连接券商、不发送真实订单，也不是把历史收益重新包装成实时成绩。

## 第一次使用

先更新本地行情并通过数据健康检查，然后运行：

```powershell
.\run_paper_trading.cmd
```

脚本会依次更新数据、生成清单、尝试 `paper-run`；若账户组还不存在，才运行一次 `paper-init`。首次初始化只在最新已验证行情日建立两个独立账户：SMA 20/60 与 120 日动量。它不会为过去日期补写成交或收益。

## 每天发生什么

收盘后，程序只用截至当天收盘的价格生成信号。若前一天留下了订单，最早在下一根通过验证的日线开盘，按固定滑点和费用**模拟**成交。随后再记录当天估值和下一笔待成交订单。

费用、最低佣金、税费和滑点均是明确的教学假设，并非你的券商费率或当下规则。模拟盘可以记录有公告证据的 ETF 现金分红，但尚未处理拆分合并、停牌、部分成交和盘口排队。

## 可选：登记一笔现金分红

程序不会猜测分红，也不会把第三方接口里字段不完整的数据自动记成现金。只有你提供了包含登记日、除息日、支付日、每份金额和 HTTPS 公告链接的本地快照，`paper-run` 才会处理。

1. 复制 `config/cash_distribution_template.csv`。
2. 把副本放到 `data/raw/cash_distributions/`，使用不会重复的文件名，例如 `2026-01-510300.csv`。
3. 在表头下面填写一行；旧文件以后不要修改，每次新公告只新增文件。
4. 必须在登记日被模拟盘处理前放入文件；迟到快照会中止，不能静默补账。

示例格式（金额和日期只是格式示范，不是真实公告）：

```csv
symbol,record_date,ex_date,payment_date,cash_per_share,currency,source_url,source_published_at,ingested_at
sh.510300,2026-01-19,2026-01-20,2026-01-22,0.1234,CNY,https://example.com/official-notice,2026-01-15T08:00:00+08:00,2026-01-15T09:00:00+08:00
```

登记日收盘持有的份额会锁定为待到账权益；支付日若不是交易日，则在其后的第一根已验证日线记入现金。即使支付日前已经卖出，已锁定的权益仍会到账。无持仓也会留下“已核对但无权益”的事件。

## 可选：登记同代码份额调整

基金份额折算会同时改变份额数量和每份价格。程序只支持最小而确定的子集：同一个 ETF 代码按明确比例放缩，并且你的模拟持仓乘以该比例后必须恰好是整数份。交易所需要集中排序或随机处理的零碎份额，程序无法从公告比例推导，因此会停止而不是擅自四舍五入。

1. 复制 `config/share_adjustment_template.csv`。
2. 把副本放到 `data/raw/share_adjustments/`，每份公告使用一个新文件，旧文件不得覆盖。
3. 用整数分数填写比例；例如每 2 份变 3 份，分子为 `3`、分母为 `2`。
4. 在生效日被模拟盘处理前放入文件；迟到快照会被拒绝。

格式示例（并非真实公告）：

```csv
symbol,effective_date,ratio_numerator,ratio_denominator,source_url,source_published_at,ingested_at
sh.510300,2026-01-20,3,2,https://example.com/official-notice,2026-01-15T08:00:00+08:00,2026-01-15T09:00:00+08:00
```

调整发生在生效日开盘订单之前：前一日留下的卖单会卖出调整后的全部份额；生效日开盘才买入的份额不会再次参与调整。公司行动可以形成非整手但仍为整数的持仓，后续清仓会卖出完整数量。

这一保守口径依据上交所《上市开放式基金业务指引》的份额折算原则：同代码放缩可以高于或低于 1，但不足 1 份的零碎份额由登记结算系统按全市场规则处理，本地模拟账户不能自行复现。参见[上交所业务指引](https://www.sse.com.cn/lawandrules/sselawsrules2025/fund/trading/c/c_20250519_10779392.shtml)。

## 结果怎么看

每次成功处理后，`outputs/` 会有 `default_paper_latest_report.html`。它同时展示两个账户的现金、份额、权益、回撤、待成交订单、待到账分红、累计分红到账、份额调整次数、数据来源和完整 SHA-256。逐日 CSV、成交 CSV、分红 CSV、份额调整 CSV、JSON 和图片也会以稳定身份归档。

如果数据陈旧、更新摘要损坏、文件哈希变化或账本审计失败，程序会停止而不是猜测成交。可以先运行：

```powershell
.\.venv\Scripts\python.exe -m finance_lab.cli paper-status
```

它只读审计账本，不会新增事件。

## 这课的边界

- 它是学习与研究工具，不是投资建议。
- 它不连接券商，也不包含真实资金或凭证。
- 一旦看过某段历史，不应把它称作新的样本外证据；前向观察从首条 `ACCOUNT_CREATED` 事件开始。
