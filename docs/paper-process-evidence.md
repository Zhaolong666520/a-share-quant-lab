# 每日运行的进程证据

本协议只增强中断留证和只读判断，不改变来源窗口、健康门槛、策略或账本提交规则。原应用归档仍为schema 2，原月日志的started/succeeded/failed格式保留。进程记录使用独立schema 1。

## 启动与输出

PowerShell在业务前创建独占launch目录和launcher.json，记录自身PID、精确创建FILETIME及脚本SHA。随后隐藏启动Python，保存实际子PID与创建时间。Python引导模块先打开独占stdout.log/stderr.log，再加载业务依赖；两份文件由Python自己持有，外层脚本消失后仍可写入。faulthandler开启，可在能够处理的异常中留下额外线索，但不保证断电或操作系统强杀时留全日志。

真正执行业务的Python会等待子进程身份记录（最多5秒），核对自身或venv父启动器与该身份一致，再写started记录及逐阶段进入记录。身份采用PID+创建时间，避免把复用PID当原进程。阶段记录只证明进入该阶段，不能证明数据或账本已经提交。

记录位置为数据根下`outputs/paper_process_runs/<portfolio>/<launch_id>/`。结束时分别保存子进程原始有符号/无符号/十六进制退出码及外层退出记录。应用归档完成后另存路径、attempt_id和SHA绑定。留证失败必须非零退出；它可能发生在业务已提交后，因此不能直接重新执行。

## 只读状态的边界

运行状态命令增加process_evidence。只有相互一致的归档、身份和退出记录才能表示completed；它仍不等于完整自然运行验收。外层已退出而worker仍活跃时单列`wrapper_exited_worker_running`。权限不可读、损坏、矛盾、读取期间变化或超过上限均保留未知。扫描上限为512次launch、当前launch20项、单条JSON64KiB、归档1MiB。

系统任务实例与应用的关联仍标为未验证，必须在自然验收时用任务事件、包装器PID及创建时间等证据独立核对。不会从任务Ready、进程记录或旧成功推断可以安全重跑或恢复。

代码可以通过既有Junction导入，身份记录保存原路径及解析后的真实路径/SHA；数据和证据目录仍拒绝reparse路径。新恢复根的历史通过外置索引指向原根与事故快照，不复制旧latest伪装新成功。

## 已覆盖的故障场景

隔离测试使用合成操作，禁止连接行情源，覆盖普通异常、硬退出、原生非零退出、依赖导入失败、父进程结束后继续输出、留证写入失败、PID复用、拒绝读取、JSON损坏、退出冲突、时间倒序及读取中增长。它们不证明2026年11月4日原生崩溃已复现或根因已修复；下一步仍须自然计划运行验收。
